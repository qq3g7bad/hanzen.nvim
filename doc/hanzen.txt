1. INTRODUCTION						*hanzen-introduction*

hanzen.nvim exposes the folds NFKC performs as separate, directional
verbs. You can apply one verb at a time, scoped to a range or visual
selection.

	katakana    hankaku -> zenkaku     ｱｲｳ ｶﾞ ﾊﾟ -> アイウ ガ パ
	alphanum    zenkaku -> hankaku     ＡＢＣ １２３ ！ -> ABC 123 !
	space       zenkaku -> hankaku     U+3000 -> ASCII (config: space_*)
	compat      ligature -> decomposed ㍻ -> 平成, ㎏ -> kg, ㍿ -> 株式会社
	enclosed    enclosed -> bare       ㈱ -> (株), ㊙ -> 秘, ㋿ -> 令和
	all         every verb above       runs each in registration order
	flush-all   like 'all', but also converts a leading-indent U+3000 run
	            (ignores space_keep_leading_indent for this one call)

"katakana" composes dakuten/handakuten (e.g. ｶﾞ -> ガ, ﾊﾟ -> パ,
ﾜﾞ -> ヷ) and touches only the halfwidth katakana block (U+FF61..U+FF9F).
A lone ﾞ / ﾟ becomes the spacing mark ゛ / ゜ (U+309B / U+309C), not the
combining U+3099 / U+309A that NFKC would produce.

"alphanum" covers the fullwidth ASCII block (U+FF01..U+FF5E): letters,
digits and symbols. The fullwidth space U+3000 is left for 'space'.

"compat" covers the CJK Compatibility block (U+3300..U+33FF) — square
katakana abbreviations, SI/derived units, era names (㍻ ㍼ ㍽ ㍾),
株式会社 (㍿), and day/score lookups (1日..31日, 0点..24点).

"enclosed" covers the Enclosed CJK Letters and Months block
(U+3200..U+32FF) — parenthesized abbreviations (㈱ -> (株), ㈲ -> (有)),
circled ideographs (㊀ -> 一, ㊙ -> 秘), enclosed numerals 21..50
(㉑ -> 21), circled month abbreviations (㋀ -> 1月), circled katakana
(㋐ -> ア), and the Reiwa era ㋿ -> 令和. These are the common
"機種依存文字" (platform-dependent characters) of Japanese business
documents.

2. WHY NOT NFKC						*hanzen-why-not-nfkc*

Unicode NFKC folds every transformation it knows in one pass: width
changes, halfwidth-kana composition, CJK Compatibility decomposition
(㍻ -> 平成, ㎏ -> kg), circled-numeral flattening, and more. It is
the right tool when ALL of those at once is what you want.

hanzen exposes the same folds, but one verb at a time:

- Independent, directional verbs. :Hanzen katakana only composes
  halfwidth katakana. :Hanzen compat only decomposes the CJK
  Compatibility block. You can fix stray halfwidth katakana without
  rewriting fullwidth brackets, or normalize unit ligatures without
  touching spaces.
- 'all' is the complete verb set, applied in one pass. When a verb is
  added to hanzen, 'all' (and 'flush-all') grow to include it.
  Behavior changes between releases are recorded in CHANGELOG.
- Pure Lua, no external dependency.
- In-editor and range-aware: :Hanzen <Tab> completion, dry-run preview
  (:Hanzen!), visual/range scoping, and a small Lua API.

If you want every fold at once outside the editor, use NFKC (nkf,
jaconv, mojimoji, ...). If you want them as separate verbs in the
buffer, use this.

==============================================================================
NON-GOALS						*hanzen-non-goals*

Some things are deliberately out of scope:

- No context inference by default. hanzen converts the lines it is
  given. Scope it with a range, a visual selection, or
  `protect = "treesitter"` (skips Markdown code blocks and inline
  code in buffers whose filetype maps to the markdown parser; other
  filetypes have nothing protected; falls back to no protection if no
  parser is available — it never guesses).
- No lossy reverse direction. Fullwidth katakana -> halfwidth,
  ASCII -> fullwidth ASCII, etc. are not provided. mojimoji and other
  dedicated tools cover that direction.
- No other whitespace. ASCII spaces, tabs, trailing whitespace and
  line endings are not normalized. The 'space' verb is U+3000-only.
- Per-verb scope is the Unicode block. Each verb operates inside its
  named block. Cross-block conveniences belong in new verbs.

'all' (and 'flush-all') is the complete set of registered verbs in
order. When a verb is added, 'all' extends to include it — this is
by design; behavior changes are recorded in CHANGELOG.

3. THE :HANZEN COMMAND						*:Hanzen*

							*hanzen-command*
:[range]Hanzen[!] [{subcommand}]

	{subcommand} is one of "katakana", "alphanum", "space", "compat",
	"enclosed", "all", "flush-all". With no argument the configured
	default is used (|hanzen-config|).

	[range]   restricts conversion to the given lines. With no range
		  the whole buffer is converted. Visual selection works
		  via :'<,'>Hanzen.

	!	  dry-run. Reports which lines WOULD change via
		  |vim.notify| and makes no edits.

	Only the changed characters are rewritten: marks, extmarks
	(diagnostics, signs) and the cursor stay on the text they were
	on, and one |undo| reverts the whole command. A non-modifiable
	buffer is reported, not an error.

Examples: ~
>
	:Hanzen katakana
	:Hanzen! alphanum
	:'<,'>Hanzen alphanum
	:10,20Hanzen all
	:Hanzen flush-all
<
Completion of {subcommand} is available with <Tab>.

4. LUA API						*hanzen-api*

							*hanzen.convert()*
require("hanzen").convert({name}, {opts})

	{name}	"katakana" | "alphanum" | "space" | "compat" |
		"enclosed" | "all" | "flush-all"
	{opts}	optional table: >
		{ line1 = <int>, line2 = <int>, dry_run = <bool>,
		  protect = "none" | "treesitter" }
<		`protect` defaults to the configured value.
	Returns: >
		{ changed = <int>, lnums = <int[]>,
		  dry_run = <bool>, blocked = <bool>,
		  protect = <string>, degraded = <bool> }
<		`lnums` lists each changed line once, in ascending order.
		`degraded` is true when `protect = "treesitter"` was asked
		for but no Markdown parser was available.
							*hanzen.setup()*
require("hanzen").setup({opts})		see |hanzen-config|.

==============================================================================
5. CONFIGURATION					*hanzen-config*

Defaults: ~
>
	require("hanzen").setup({
	  default = "katakana",             -- bare :Hanzen subcommand
	  notify  = true,                   -- vim.notify summary after running
	  space_repeat = 1,                 -- U+3000 -> this many ASCII spaces
	  space_keep_leading_indent = true, -- false: also convert a leading
	                                    -- U+3000 run
	  protect = "none",                 -- "treesitter": skip Markdown code
	})
<
setup() is optional; :Hanzen works without it. If any option is invalid
(an unknown `default` or `protect`, a negative or fractional
`space_repeat`, a non-boolean flag), setup() reports it with an error and
applies none of the options.

==============================================================================
6. EXTENDING						*hanzen-extending*

Each converter is a pure function(text, ctx) -> text. `text` is a line,
or the part of one between protected spans; `ctx.at_line_start` says
whether it begins the line. Most converters ignore `ctx`.

To add one, create lua/hanzen/<name>.lua exposing convert(), then
register it in the `converters` table in lua/hanzen/init.lua and add its
name to `ALL` (every verb belongs to 'all'; loading fails otherwise).
Subcommands and completion are derived from `ALL`, and the command and
range engine need no changes.
